# 人生ログデータ仕様書(生活リズム帳 バックアップファイル形式)

この文書は、「生活リズム帳」のバックアップファイル(.json)の構造を、
別のプログラムやアプリへデータを移行する開発者向けに説明するものです。

## 1. 全体構造(トップレベル)

```json
{
  "archiveInfo": { ... },
  "app": "生活リズム帳",
  "backupVersion": 2,
  "exportedAt": "2026-08-02T12:00:00.000Z",
  "formatGuide": { ... },
  "data": { ... },
  "photos": [ ... ]
}
```

| 項目 | 型 | 説明 |
|---|---|---|
| `archiveInfo` | object | このアーカイブ自体の説明(タイトル・作成日・文字コード等)。人間向け |
| `app` | string | アプリ名。常に `"生活リズム帳"` |
| `backupVersion` | number | バックアップ形式のバージョン番号。`1`=写真を含まない旧形式、`2`=写真を含む形式 |
| `exportedAt` | string | 書き出し日時(ISO 8601形式) |
| `formatGuide` | object | 各項目の意味を日本語で説明したもの。人間向け(復元処理では使用しない) |
| `data` | object | 実際の記録データ本体(詳細は下記2) |
| `photos` | array | 写真データ本体(詳細は下記3、`backupVersion:1`では存在しないことがある) |

**互換性の原則**: 将来のバージョンで新しい項目が追加されても、`data`と`photos`
さえ読めれば過去の全記録を復元できます。逆に、未知の項目が含まれていても
無視して構いません(このアプリ自身もそのように実装されています)。

## 2. data(記録データ本体)

`data`は、キーと値の組(オブジェクト)です。キーの種類ごとに意味が異なります。

### 2-1. `log:YYYY-MM-DD` (1日ごとの記録)

キー例: `log:2026-08-02`

値(JSON文字列をパースしたもの)の構造:

```json
{
  "sleepStart": "23:00",
  "sleepEnd": "06:30",
  "meals": {
    "breakfast": { "time":"07:00", "content":"パン", "nutrition": {...}, "skipped": false },
    "lunch": { ... },
    "dinner": { ... }
  },
  "taiso": true,
  "bath": true,
  "souji": false,
  "sentaku": true,
  "schedule": "通院予定",
  "todos": [ { "text":"薬を飲む", "done": true } ]
}
```

| 項目 | 意味 |
|---|---|
| `sleepStart` | 就寝時刻(24時間表記、"HH:MM") |
| `sleepEnd` | 起床時刻 |
| `meals.breakfast/lunch/dinner` | 朝食/昼食/夕食。`time`=食べた時刻、`content`=内容の自由記述、`nutrition`=推定栄養価(参考値)、`skipped`=食事をとらなかったか |
| `taiso` | 習慣チェック1(既定ラベル「ラジオ体操」。ユーザーが任意の名称に変更できるため、`formatGuide`内に実際のラベルが記録されている) |
| `bath` | 習慣チェック2(既定ラベル「湯船」、同上) |
| `souji` | 習慣チェック3(掃除をしたか) |
| `sentaku` | 習慣チェック4(洗濯をしたか) |
| `schedule` | その日の予定・メモの自由記述 |
| `todos` | やることリスト(その日に完了した項目)。`text`=内容、`done`=完了フラグ(常にtrue) |

### 2-2. `prep:YYYY-Wnn` (週ごとの作り置き記録)

キー例: `prep:2026-W32`(2026年第32週)。`note`(メモ)と`cookedDate`等を含む。

### 2-3. その他の固定キー

| キー | 意味 |
|---|---|
| `userSettings` | アプリの表示設定(文字サイズ・色・習慣チェックのラベル名など) |
| `activeTodos` | まだ完了していない「やることリスト」 |
| `prepStatus` | 直近の作り置き実施日 |
| `lastViewedDate` | 最後に開いていた日付(単なる操作履歴、記録の本体ではない) |

## 3. photos(写真データ)

配列の各要素:

```json
{ "key": "2026-08-02_breakfast", "mimeType": "image/jpeg", "base64": "..." }
```

| 項目 | 意味 |
|---|---|
| `key` | `YYYY-MM-DD_食事種別`(breakfast/lunch/dinner)の形式。どの日のどの食事の写真かを表す |
| `mimeType` | 画像形式。通常 `image/jpeg` |
| `base64` | 画像データをBase64(標準的なテキストへの変換方式)にしたもの |

**元の画像ファイルへ戻す方法**: `base64`の文字列を、一般的なプログラミング言語の
Base64デコード機能(例: Python `base64.b64decode()`、JavaScript `atob()`)で
デコードし、`.jpg`拡張子で保存すれば、通常のJPEG画像ファイルとして開けます。

**撮影日の情報について**: 画像ファイル自体にはEXIF情報(撮影日時等)は保持して
いません(アプリ内で表示用に画像を縮小・再圧縮する際に失われるため)。
撮影日・食事の種類は、この`key`(ファイル名相当)にのみ記録されています。
写真を個別ファイルとして取り出す際は、`key`をそのままファイル名として
使うことを強く推奨します(例: `2026-08-02_breakfast.jpg`)。

## 4. バージョン管理・移行方法

- `backupVersion`は今後も後方互換を維持する方針で運用されています。新しい
  バージョンのアプリは、常に古いバージョンのバックアップを読み込めます。
- 別のアプリ・システムへ移行する場合は、`data`内の`log:*`キーを日付ごとの
  レコードとして読み込み、`photos`内の`key`と突き合わせることで、
  「その日、何を食べて、どんな写真を撮ったか」を完全に再構築できます。
- 文字コードは常にUTF-8です(JSON標準の仕様に準拠)。絵文字や日本語を
  含む記述も、標準的なJSONパーサーであれば問題なく復元できます。
